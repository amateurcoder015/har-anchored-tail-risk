# Pre-registration: fresh-universe test

Written on 2026-10-06 and pushed to GitHub before any data for the assets below was downloaded or inspected. The code used for the test is the commit tagged `prereg-fresh` (the commit that adds this file). The GitHub commit timestamp is the record of the order.

## Background

- Predecessor project (pre-registered held-out study on 12 stocks): a state-dependent neural combination gate did not beat simple combinations; HAR on range-based variance was the only member of the 10% Model Confidence Set.
- This project's development universe (20 assets, `docs/devlog.md`): R0 (HAR) had the lowest pooled FZ0 at all tail levels. R1 (HAR-X fitted on FZ0) and R2 (bounded correction of HAR) did not beat it. A penalty on the average correction (level control) moved R2-MLP from clearly behind HAR to a tie.
- Literature check (spec section 10): no pre-registered VaR/ES forecasting study found; level drift as a cause of combination failure follows Claeskens et al. (2016), Elliott and Liao (2026) and Clements and Hendry.

Mechanical rules applied after download (no judgement):
- An asset with fewer than 95% of the trading days of the asset with the most rows is removed before any modelling, and the removal is reported.
- Outliers (|r| > 10%): a row is dropped only if raw and adjusted prices show an unadjusted split, bonus or demerger on that date; all other rows are kept.

## Protocol

Identical to the development runs at the tagged commit: data 2015-01-01 to 2026-09-30; base models and baselines refitted every 21 trading days on an expanding window; gates (`gate`, `gate_v2`) and R2 trained pooled across the fresh assets with the predecessor's yearly folds; R2 anchored on R0 with λ_c = 1 and λ_m = 100 (`configs/fresh.yaml`); test period 2023-01-01 to 2026-09-30; pooled tests on the cross-asset average FZ0 loss per date.

## Hypotheses (α = 2.5%, pooled)

Each is a one-sided Diebold–Mariano test (Newey–West variance, HLN correction) that the first method has lower mean FZ0 than the second. Holm correction across H1–H4, family-wise level 0.05. Implemented in `src/hart/hypotheses.py` and run by `scripts/12_hypotheses.py`.

- **H1:** R0 (HAR) < equal-weight mean of the six base models.
- **H2:** R0 < Taylor (2020) minimum-score combination.
- **H3:** R0 < original gate (`gate`, no level control).
- **H4:** `gate_v2` (level control) < `gate`.

Secondary, no multiplicity claims: R2-MLP < R0, R2-linear < R0, R1 vs R0; Model Confidence Set (10%); Kupiec, Christoffersen, DQ and McNeil–Frey backtests; α = 1% and 5%; per-asset and by-year results.

## Commitments

- The fresh study is run once. After download, only crash fixes are allowed, each listed with its reason in the results.
- All hypotheses are reported whatever the outcome, in the README and in any paper.

## Development dry run (for transparency)

`scripts/12_hypotheses.py` was run on the development universe before registration (`results/dev/tables/hypotheses.csv`). One-sided DM p-values after Holm correction: H1 0.028 (supported), H2 0.150 (not supported), H3 0.012 (supported), H4 0.013 (supported). These numbers come from the data the methods were developed on and are not evidence for the fresh test.
